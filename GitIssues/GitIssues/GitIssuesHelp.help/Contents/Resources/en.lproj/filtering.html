Filtering Issues

The filter bar sits below the search box and lets you narrow the issue list by multiple criteria at once. All filter settings are saved and restored when you relaunch the app.

State Filter

A segmented control with three options:

OptionShows
AllBoth open and closed issues
OpenOpen issues only (default)
ClosedClosed issues only

Visibility Filter

Filter by whether a repository is public or private:

OptionShows
AllIssues from all repositories (default)
PublicOnly issues from public repositories
PrivateOnly issues from private repositories
Note Private repositories only appear if you have enabled private access in Settings and re-authenticated with GitHub.

Involvement Filter

Filter by your relationship to the issue:

OptionShows
AllAll issues regardless of your role (default)
Created by meOnly issues you opened
Assigned to meOnly issues assigned to you
OtherIssues you neither created nor are assigned to

Repository Filter

This filter only appears if your account has two or more repositories. Click the Repos button to open a picker sheet and select or deselect individual repositories. The button label updates to show how many are selected (e.g. 3 selected). Click Clear in the sheet to restore all repositories. Repositories are listed alphabetically by name, ignoring case.

Label Filter

This filter only appears if any of your issues have labels. Click the Labels button to open a picker sheet where you can search for and select one or more labels.

  • The search field inside the sheet filters labels by name in real time.
  • Selecting multiple labels uses OR logic — an issue appears if it has at least one of the selected labels.
  • Click Clear to deselect all labels.
  • Each label is shown with its colour badge for easy identification.

Combining Filters

All active filters are applied together (AND logic between different filter types). For example, selecting Open state, Assigned to me, and a specific label shows only your open assigned issues that carry that label.

Tip The issue count in the header (e.g. Issues (12)) always reflects the number of issues currently matching all active filters.
