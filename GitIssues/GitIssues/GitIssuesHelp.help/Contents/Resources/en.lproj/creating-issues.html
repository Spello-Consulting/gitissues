Creating Issues

Click the + button in the toolbar (or press ⌘ N) to open the Create Issue window.

Filling In the Form

Repository (required)

Choose the repository in which to create the issue from the dropdown menu. The repository defaults to the one used for the last issue you created or edited since GitIssues was launched; the first time after launch it is left blank. Selecting a repository loads the labels available for that repository.

Title (required)

Enter a short, descriptive title. The form cannot be submitted without a title.

Description (optional)

Write the issue body using the Markdown editor. The toolbar above the editor provides buttons for common formatting: bold, italic, headings, blockquotes, lists, links, images, code, and tables. A preview mode and side-by-side view are also available via the toolbar.

Initial Comment (optional)

You can attach a first comment to the issue at creation time. This is useful for providing additional context or a discussion starter without cluttering the issue description. The comment is posted immediately after the issue is created.

Labels (optional)

Click any label badge to select it. Selected labels show a checkmark and a darker background. Click again to deselect. You can select as many labels as you like.

If the label you need does not exist yet, click the + button next to the Labels heading to create one. See Labels for details.

Submitting

Click Create Issue to publish the issue to GitHub. The button is disabled while the request is in progress. Once created, the issue appears at the top of your list and is automatically selected in the detail panel.

Click Cancel to close the window without creating anything.

Tip The new issue scrolls into view automatically and is selected so you can review it straight away.

Validation

If the title is empty or no repository is selected, an error message is shown and the issue is not submitted. Correct the highlighted fields and try again.
